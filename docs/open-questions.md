# 規則確認與技術待辦

更新日期：2026-10-10。Q-01～Q-10 已由使用者逐項確認並要求同步文件；下表是決議，不再是待選建議。技術事項仍依開發順序處理。

## 已確認商業問題

| 編號 | 原問題 | 已確認結果 | 影響 | 狀態 |
|---|---|---|---|---|
| Q-01 | 重複包裹 | 同棟相同物流公司及單號先顯示既有紀錄，管理員確認後仍可新增；缺少物流公司或單號不比對。 | BR-06、F-07、AC-3A | 已確認，見 [D-07](decisions.md) |
| Q-02 | 帳號功能範圍 | 第一版維持註冊、登入、登出、修改姓名電話；修改密碼、忘記密碼及帳號啟停介面列後續。 | BR-02、F-01、F-02、AC-2A | 已確認，見 [D-08](decisions.md) |
| Q-03 | 無法電子簽收 | 仍由住戶本人確認，管理員不可代簽；未確認先留櫃檯，已交付未簽收先記錄異常並聯絡核對，恢復流程後本人確認，原有資格限制仍適用。 | BR-07、F-09、F-11、AC-3B | 已確認，見 [D-09](decisions.md) |
| Q-04 | 邀請碼 | 系統自動產生四位數字字串，保留開頭的0；全系統有效碼唯一，固定24小時到期，可提早停用或重發，新碼使舊碼失效。 | BR-05、F-06、AC-2D | 已確認，見 [D-10](decisions.md) |
| Q-05 | 取件碼及防猜 | 取件碼六位數字、同棟有效碼唯一；邀請碼與取件碼分別連錯5次，暫停該帳號對應驗證功能5分鐘，不影響其他功能。邀請碼驗證與確認加入共用失敗計數。 | BR-05、BR-07、F-06、F-09、AC-2D、AC-3B | 已確認，見 [D-11](decisions.md) |
| Q-06 | 登入期限 | 登入成功起8小時到期，須重新登入；登出只影響目前裝置，後端使當次登入失效，其他裝置不受影響。 | BR-02、F-01、AC-2A | 已確認，見 [D-12](decisions.md) |
| Q-07 | 更正包裹 | 資料實際有變動就取消等待中的驗證，重新核對；只有更改入住歸屬時因本次更正換取件碼，其餘更正保留碼。異常恢復領取的換碼規則仍適用。 | BR-06、F-07、F-09、AC-3A、AC-3B | 已確認，見 [D-13](decisions.md) |
| Q-08 | 管理員分配畫面 | 系統管理員在管理員管理畫面選擇姓名及大樓，前端背景傳帳號ID；提供含已分配與未分配帳號的管理員列表，可調整大樓或取消分配，不要求手動輸入ID或Email查找。 | BR-02、F-04、AC-2B | 已確認，見 [D-14](decisions.md) |
| Q-09 | 重新加入 | 已取消資格者取得新有效邀請碼，且無其他有效或等待退出資格時可重新加入；保留舊紀錄、建立新資格，不增加封鎖名單。 | BR-04、F-06、F-12、AC-2D | 已確認，見 [D-15](decisions.md) |
| Q-10 | 歷史顯示 | 只有簽收者及經手管理員姓名保存簽收當時值；大樓名稱、樓層、戶號、收件人、物流公司及單號顯示目前關聯資料。 | BR-07、F-10、AC-3B | 已確認，見 [D-16](decisions.md) |

## 工程師需提出並驗證的技術事項

這些不是要求使用者選資料庫演算法；工程師應給出可驗證的實作方案。若方案影響上表的商業行為，仍須先確認。

| 編號 | 項目 | 建議方向 | 完成時機 |
|---|---|---|---|
| T-01 | 時區、字元集、Email 正規化、日期篩選邊界 | UTC 儲存、ISO 8601 傳輸、臺灣時間顯示；明確記錄比較規則 | 階段 2 建表前 |
| T-02 | 有效入住、資格、邀請碼、驗證的唯一性與交易 | 資料庫限制搭配一致鎖定順序；以並行測試驗證，不能只先查再新增 | 對應功能開始前 |
| T-03 | 邀請碼雜湊查找、取件碼加密查找與碰撞 | 分離密文與查找值，金鑰由環境設定提供，避免將原碼記錄於日誌 | F-06 / F-07 前 |
| T-04 | 登入憑證撤銷、CSRF、限流與密碼雜湊 | 依 Q-05、Q-06 決議選方案，補必要欄位或技術資料表並更新設計 | F-01 前；取件限流於 F-09 前 |
| T-05 | SQL 升級與開發資料初始化 | 有版本腳本，測試資料重跑不重複，不清除 mysql_data | 階段 2 開始 |
| T-06 | 前後端同步與斷線恢復 | 第一版建議等待畫面輪詢，停止及重試條件明確；依 Q-03 已確認現場流程 | F-09 前 |
| T-07 | 統一錯誤與 API 完整驗證 | 對齊 FastAPI 實際回應、Swagger、型別與測試 | 每個功能驗收前 |
| T-08 | 專案版本管理 | 已解決（D-21）：根目錄統一 Git 並關聯 GitHub；frontend 獨立 Git 備份後移除，不匯入歷史 | 2026-10-11 完成 |

## 新問題的記錄方式

新增問題須說明具體情境、現有依據、選項、建議、受影響功能；不因問題清單暫時沒有某情境就自行推定規則。與未定規則無關的已確認文件可以持續整理。
