## review 發現與修正

1. **驗收程序啟動逾時仍繼續執行**：改成共用 `test_support.wait_for_server`，子程序退出、等待逾時都停止；加入正常、重試、逾時、先退出、探測期間退出等 5 項測試。
2. **回應型別在執行時動態產生，不利新手理解**：改為 `schemas/outputs.py` 的 24 個明確類別，路由直接引用；新增契約比對與安全回應測試，原有業務驗收重新通過。
3. **備份還原與重啟只有文件，缺少實測證據**：新增 `database_recovery.py`，僅允許固定來源測試庫、只還原至新庫；加入 4 項安全邊界測試，完成真實 mysqldump／restore／restart 比較。
4. **日期邊界、分頁與 migration 失敗保護證據不夠具體**：補上獨立測試庫案例，確認臺灣午夜、起迄日期、排序總數、checksum 與 applying 狀態。
5. **業務服務壓縮寫法與文件狀態過時**：展開條件和邀請碼迴圈、統一格式；新增後端閱讀說明，修正 Swagger「尚未實作」說明並同步生成來源與結果。

review 範圍包含所有業務路由、輸入／回應模型、交易服務、帳號 repositories、登入／來源／錯誤處理、碼與限流、初始化、migration 及 13 份 DDL。未發現仍待修復的本版後端功能阻斷問題。

## 邊界與後續

本機 MVP 以單資料庫業務鎖、直接 SQL 和明確回應類別維持容易理解的架構；不以大量資料或高併發效能為本次驗收條件。加密金鑰仍須與實際資料備份分別安全保存，SQL 本身不含金鑰。

T-06 的畫面輪詢、斷線重試，以及手機桌面、前端登入導向和角色全流程整合，依 D-26 留給前端階段。不得以本次後端結案勾選 AC-2B～3E 的整項畫面驗收。
