# 大樓包裹系統商業邏輯

更新日期：2026-10-15。Q-01～Q-10 已確認並同步。D-26 調整開發順序為先完成 DB／後端、再由使用者製作前端；商業行為不變。實際進度見開發計畫，技術事項見 [確認與待辦清單](open-questions.md)。

本文件整理既有資料庫與 API 文件中已明確的規則，以及本次對話決議。若規則與其他文件或程式不一致，先詢問使用者，不自行選擇版本。

## BR-01 角色與資料權限

- 一個帳號只有一種角色：系統管理員、大樓管理員或住戶。
- 系統管理員建立與管理大樓、建立大樓管理員並分配管理範圍。依現有 API，系統管理員不直接操作住戶、包裹或簽收。
- 一棟可有多位大樓管理員；每位管理員同時只負責一棟。取消分配後立即失去原大樓操作權，但保留歷史經手紀錄。
- 大樓管理員只能管理被分配大樓的資料，包括歷史紀錄。
- 住戶只有在帳號啟用、資格為 active 或 exit_requested、入住尚未結束時，才能查看及操作所屬入住的資料。
- 同批次成員共用包裹與簽收紀錄；晚加入者也可查看。不同戶、不同入住批次與已搬離者不能查看。
- 權限由後端於每次操作重新檢查，不能只靠畫面隱藏按鈕或登入時的舊資料。

## BR-02 帳號

- 以 Email 與密碼登入；Email 不可重複，電話為聯絡資料，不作簡訊登入。
- 公開註冊固定建立住戶，不能傳入管理員角色；首個系統管理員由初始化建立。
- 大樓管理員由系統管理員建立；已存在的 building_admin 可重新分配，但必須先解除原分配。
- 系統管理員在管理員管理畫面選擇姓名及大樓，前端背景傳帳號ID；提供含已分配與未分配帳號的管理員列表，可調整大樓或取消分配，不要求手動輸入ID或Email查找。
- 姓名、電話可修改；角色、Email 與戶別不透過個人資料修改功能變更。
- 帳號姓名在註冊及修改個人資料時統一最多 100 字元（D-24）。
- 停用帳號不能登入或使用受保護功能；取消入住資格不等於停用帳號。
- 註冊完成後再登入；登出清除登入 Cookie，重複登出回傳成功。登入成功起8小時到期，須重新登入；登出使目前裝置的當次登入失效，不影響其他裝置。
- 第一版維持註冊、登入、登出、修改姓名電話；修改密碼、忘記密碼及帳號啟停介面列後續。
- 2A 驗收包含三角色登入導覽、住戶尚未加入及管理員等待分配提示；已有入住／分配的真實關聯查詢與驗收留至 2B／2D（D-25），不以空陣列代表關聯查詢完成。

## BR-03 大樓與戶別

- 大樓名稱可重複，以 ID 區分，畫面搭配地址辨識；只有系統管理員可刪除沒有管理員分配、戶別及任何業務紀錄的大樓；有任一關聯資料時拒絕刪除，不連帶刪除關聯資料。
- 系統管理員建立大樓；大樓管理員可修改自己大樓的基本資料。
- 同棟戶號不可重複，不同棟可重複。樓層與戶號為文字，可使用 3F、B1、3A 等。
- 更正戶別只改樓層與戶號，不改所屬大樓與成員；搬離不刪除戶別。

## BR-04 入住與成員資格

- 「入住批次」代表同一戶的某一批住戶，畫面稱「入住」。每戶同時只有一個有效入住。
- 同家人或室友加入既有入住；整戶換人時，結束舊入住再建立新入住。
- 每位住戶同時最多有一筆 active 或 exit_requested 資格。等待退出仍保有權限並占用資格。
- 加入時必須已登入、帳號啟用、角色為住戶。驗證邀請碼只顯示大樓戶別，不授予權限。
- 住戶確認加入時再檢查邀請碼、入住與資格；不接受前端指定他人帳號或任意入住 ID。
- 已加入同批次的重試回傳既有資格，不重複新增；已有另一戶有效資格則拒絕。並行請求不能加入兩戶。
- 舊資格保留，日後重新入住建立新紀錄；個別搬離不自動結束整戶入住。
- 已取消資格者取得新有效邀請碼，且無其他有效或等待退出資格時可重新加入；保留舊紀錄、建立新資格，不增加封鎖名單。

## BR-05 邀請碼

- 由所屬大樓管理員要求系統產生，固定24小時到期，交付經確認的屋主或入住代表；管理員不設定期限。
- 同一入住同時只保留一組有效碼，可供同批次多位成員使用。
- 原碼只在建立成功時顯示一次；之後只能查狀態及期限，不能查回原碼。
- 重新產生時停用舊碼，已加入成員不受影響；取消成員資格時停用該入住舊碼。
- 有效條件為未停用、未到期、入住未結束。錯誤、過期、停用碼不得加入。
- 產生新碼及停用舊碼須一起成功或失敗。系統自動產生四位數字字串，保留開頭的0；全系統有效碼唯一，固定24小時到期，可提早停用或重發，新碼使舊碼失效。

## BR-06 包裹登記與更正

- 管理員確認有效入住與包裹收件人後登記，產生取件碼，狀態為 pending。
- 包裹歸屬入住批次，不只歸屬戶號；不得因換住戶而自動轉移舊包裹。
- 收件人姓名必填；物流公司、物流單號、存放位置及備註選填。收件人不必等於簽收帳號姓名，同批次有效成員可代領。
- 登記者與時間由系統取得；列表與一般回應不得洩漏取件碼。
- 僅 pending、exception 包裹可更正資料；不能直接改狀態、簽收者與登記時間。
- 登記錯誤時可更正至同大樓的有效入住，須取消舊驗證並更換碼。來源入住已結束者不得轉給新住戶。
- 同棟相同物流公司及單號先顯示既有紀錄，管理員確認後仍可新增；缺少物流公司或單號不比對。
- 資料實際有變動就取消等待中的驗證，重新核對；只有更改入住歸屬時因本次更正換取件碼，其餘更正保留碼。異常恢復領取的換碼規則仍適用。

## BR-07 取件與簽收

1. 有權限住戶查看 pending 包裹的取件碼，到櫃檯提供管理員。
2. 管理員確認自己大樓、有效入住、待領狀態及碼相符，建立 10 分鐘取件驗證。
3. 驗證成功仍是待領取。管理員交付實物，住戶核對後以自己的登入帳號確認收到。
4. 後端重新檢查帳號、資格、入住、包裹、驗證及期限，再同時完成簽收紀錄、包裹狀態與驗證狀態，取件碼失效。

- 同包裹同時只有一筆有效驗證。同管理員重試取得原結果，其他管理員遇到有效驗證回傳衝突。
- 只有經手管理員或有包裹資格的住戶能查驗證進度；經手管理員可取消未完成驗證，不能取消已完成簽收。
- 過期或取消不代表已領取；必須重新核對現場情況後再驗證。仍由住戶本人確認，管理員不可代簽；未確認先留櫃檯，已交付未簽收先記錄異常並聯絡核對，恢復流程後本人確認，原有資格限制仍適用。
- 同簽收者在仍有存取權時重試取得原結果；其他同戶成員得到已簽收提示；已失去資格者不得取得原結果。
- 一包裹只能成功簽收一次，一驗證只能對應一筆簽收，驗證與簽收必須指向同一包裹。
- 簽收者及時間由後端取得。保存簽收當時的簽收者、經手管理員姓名，改名不改歷史姓名。只有簽收者及經手管理員姓名保存簽收當時值；大樓名稱、樓層、戶號、收件人、物流公司及單號顯示目前關聯資料。
- 簽收紀錄不提供一般修改或刪除。「簽收者」指電子確認帳號，不表示系統辨識了實際拿走包裹的人。
- 取件碼六位數字、同棟有效碼唯一；邀請碼與取件碼分別連錯5次，暫停該帳號對應驗證功能5分鐘，不影響其他功能。邀請碼驗證與確認加入共用失敗計數。

## BR-08 異常與退回

- 只有所屬大樓管理員可登記未領取、未退回包裹的異常，原因必填。
- 設為 exception 時記錄操作者、時間，清空前次處理結果，取消未完成驗證；一起成功或失敗。
- 只保留最近一次異常與處理結果，不提供完整異常歷程。
- 處理 exception 時須填處理結果：恢復領取回到 pending 並換碼；實際退回物流後改為 returned。
- exception、returned、picked_up 不能領取；已簽收不能改為異常。
- 入住已結束的未領包裹只能處理退回，不得恢復領取。

## BR-09 搬離與整戶更替

- 住戶只能申請退出自己的有效資格；申請中仍有權限，重複申請回傳既有結果。
- 管理員可確認退出，亦可直接取消已搬離者資格；取消資格及停用舊邀請碼須一起完成。
- 取消個別資格不影響其他同戶成員；重試不覆寫原取消時間或停用後來產生的新碼。
- 結束整戶入住前，管理員先檢查未領包裹。
- 結束入住、取消成員資格、停用邀請碼、取消未完成驗證、將 pending 包裹標為 exception 必須一起成功或失敗。
- 搬離異常原因為「原住戶已搬離，待處理」；既有異常補充搬離原因，已簽收與已退回者不變。
- 舊包裹留在舊入住；舊住戶不能返回系統領取，後續只供管理員處理退回。
- 舊入住結束後才能建立新入住，新住戶不能看舊資料。重試已結束入住不覆寫歷史。

## BR-10 狀態與驗收原則

| 對象 | 狀態 | 合法變化 |
|---|---|---|
| 成員資格 | active / exit_requested / revoked | active → exit_requested；active 或 exit_requested → revoked |
| 入住 | ended_at 為空或有值 | 有效 → 結束；新人另建紀錄 |
| 包裹 | pending / picked_up / exception / returned | pending → picked_up；pending → exception；exception → pending 或 returned |
| 驗證 | awaiting_confirmation / completed / expired / cancelled | 等待確認 → 完成、過期或取消；終態不重開，需新驗證 |

包裹恢復 pending 仍受入住有效限制。管理員不得代簽。更改規則後，必須同步修改功能、資料設計、API 及驗收情境。
