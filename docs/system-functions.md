# 系統功能規格

更新日期：2026-10-10。功能規劃不代表完成；進度統一記錄於 [開發順序與驗收](development-plan.md)。商業規則見 [BR 規格](business-rules.md)，已確認決議與技術待辦見 [Q 清單](open-questions.md)。

## 本版基本功能

2A 階段界線（D-25）：完成三角色帳號導覽、住戶尚未加入與管理員等待分配提示；實際大樓分配及入住資格查詢於 2B／2D 實作驗收，不以空陣列視為完成。

2026-10-15 依 D-26，2B～3D 後端及上述真實關聯查詢已完成；剩餘畫面由使用者製作，後端完成不等於本表功能整項已完成。請依 [串接交接](frontend-integration.md) 接 API。

| 編號 | 角色與功能 | 畫面、輸入及結果 | 規則 | API 操作數 |
|---|---|---|---|---|
| F-01 | 全角色登入；住戶註冊；登出 | 註冊姓名、Email、電話、密碼；登入 Email、密碼；取得資格後依角色導向，無入住提示加入、無分配提示等待分配 | BR-01、02；Q-02、06 | 4 |
| F-02 | 全角色修改個人資料 | 檢視帳號、修改姓名電話；不得修改角色與戶別 | BR-02 | 1 |
| F-03 | 系統管理員建立大樓；系統與大樓管理員查閱及修改 | 列表、詳情、建立及修改；名稱地址必填、電話選填；依權限顯示範圍；系統管理員確認後可刪除無管理員分配、戶別與業務紀錄的大樓 | BR-01、03；D-27 | 5 |
| F-04 | 系統管理員建立及分配管理員 | 管理員列表、新建帳號、指派既有帳號、取消分配；一人一棟，調任先解除原分配；管理畫面顯示姓名與大樓，前端傳ID；列表包含已分配及未分配帳號 | BR-01、02 | 4 |
| F-05 | 大樓管理員管理戶別與入住 | 戶別列表、建立及更正樓層戶號、目前及歷史入住、建立入住 | BR-03、04 | 5 |
| F-06 | 管理員管理邀請碼及名單；住戶加入 | 四位數碼固定24小時、一次顯示及複製、期限狀態列表、停用；住戶輸入碼、預覽戶別、確認加入；管理員查看住戶名單 | BR-04、05；Q-04、09 | 6 |

## 本版主要功能

| 編號 | 角色與功能 | 畫面、輸入及結果 | 規則 | API 操作數 |
|---|---|---|---|---|
| F-07 | 管理員登記及更正包裹 | 選有效入住、填收件人，選填物流、單號、位置、備註；登記或更正後顯示結果 | BR-06；Q-01、07 | 2 |
| F-08 | 管理員與住戶查詢包裹 | 列表、詳情、狀態篩選、關鍵字、分頁；依大樓及有效入住限制資料，顯示驗證狀態入口 | BR-01、06 | 2 |
| F-09 | 住戶查看碼及確認；管理員驗證及取消 | 住戶顯示碼，管理員輸入碼核對；等待畫面顯示期限及狀態，住戶確認收到、管理員取得完成結果；失敗與逾時提示 | BR-07；Q-03、05、06、07 | 5 |
| F-10 | 管理員與住戶查詢簽收紀錄 | 列表、分頁及 API 支援的日期／戶別篩選；顯示簽收時姓名、時間、經手管理員；不能修改刪除 | BR-01、07；Q-10 | 1 |
| F-11 | 管理員處理異常 | 填原因、查看最近異常、填處理結果、恢復領取或確認退回 | BR-08 | 2 |
| F-12 | 住戶申請退出；管理員取消資格 | 退出申請、退出名單與直接取消；顯示申請狀態及失去資格結果，保留其他成員 | BR-09；Q-09 | 2 |
| F-13 | 管理員結束整戶入住 | 先列受影響成員及未領包裹，再確認結束；顯示結果，再建立新入住 | BR-09 | 1 |

API 合計40個：階段2為25個，階段3為15個；Q-08新增管理員總列表，其他決議更新既有請求及回應。

共用能力隨各功能開發，不能全留到最後；階段驗收須使用真實 API。區別未登入、無權限、找不到資料與狀態不允許。

## 頁面範圍

- 共用：登入、註冊、個人資料、加入戶別、權限不足及未分配提示。
- 系統管理員：大樓列表詳情、管理員列表與分配。
- 大樓管理員：大樓資料、戶別入住、邀請碼、住戶退出名單、包裹列表詳情表單、取件驗證、簽收紀錄、異常。
- 住戶：目前戶別、包裹列表詳情、取件碼與確認、簽收紀錄、退出申請。
- 新增更正確認可用對話框，不要求每個 API 都另做頁面。視覺沿用寓收預覽，行為以商業規格為準。

## 本版以外的功能

修改密碼、忘記密碼、帳號啟停介面依Q-02列後續擴充，不納入第一版。以下暫不排入本機交付：Email／簡訊通知、QR Code、照片、智慧櫃、複雜統計、多角色帳號、完整調任及異常歷程、公開部署。

僅允許系統管理員刪除無關聯資料的大樓（D-27）；不提供一般簽收修改刪除、搬離者返回領取，依商業規則辦理；不得當成 UI 漏做而自行補上。

## 已確認互動補充

- Q-01：同棟相同物流公司及單號先顯示既有紀錄，管理員確認後仍可新增；缺少物流公司或單號不比對。
- Q-02：第一版維持註冊、登入、登出、修改姓名電話；修改密碼、忘記密碼及帳號啟停介面列後續。
- Q-03：仍由住戶本人確認，管理員不可代簽；未確認先留櫃檯，已交付未簽收先記錄異常並聯絡核對，恢復流程後本人確認，原有資格限制仍適用。
- Q-04：系統自動產生四位數字字串，保留開頭的0；全系統有效碼唯一，固定24小時到期，可提早停用或重發，新碼使舊碼失效。
- Q-05：取件碼六位數字、同棟有效碼唯一；邀請碼與取件碼分別連錯5次，暫停該帳號對應驗證功能5分鐘，不影響其他功能。邀請碼驗證與確認加入共用失敗計數。
- Q-06：登入成功起8小時到期，須重新登入；登出只影響目前裝置，後端使當次登入失效，其他裝置不受影響。
- Q-07：資料實際有變動就取消等待中的驗證，重新核對；只有更改入住歸屬時因本次更正換取件碼，其餘更正保留碼。異常恢復領取的換碼規則仍適用。
- Q-08：系統管理員在管理員管理畫面選擇姓名及大樓，前端背景傳帳號ID；提供含已分配與未分配帳號的管理員列表，可調整大樓或取消分配，不要求手動輸入ID或Email查找。
- Q-09：已取消資格者取得新有效邀請碼，且無其他有效或等待退出資格時可重新加入；保留舊紀錄、建立新資格，不增加封鎖名單。
- Q-10：只有簽收者及經手管理員姓名保存簽收當時值；大樓名稱、樓層、戶號、收件人、物流公司及單號顯示目前關聯資料。
