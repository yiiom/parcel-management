## 執行規則

- 三大階段依使用者決議固定；2A、3A 等是階段內步驟。
- 每個小功能完成「所需資料庫 → 後端與 API 測試 → 前端 → 串接驗收」，不先寫完整階段後端才做畫面。
- 畫面開發可暫用假資料；驗收必須使用實際 API 與資料庫。
- 第二階段建立基本功能需要的 7 張業務表；第三階段逐步加入包裹、驗證與簽收的 3 張表。必要技術支援表另記設計，不為維持表數犧牲正確性。
- 功能開始前處理相關 Q 與 T 項目；第一階段未通過不提前開發業務功能。
- 業務規則、資料庫、API、畫面與測試同步，規則不一致先問使用者。

### AC-2A 帳號與權限

- [ ] 註冊固定住戶；重複 Email、錯誤密碼、帳號停用均正確處理。
- [ ] 只能修改自己的姓名電話，不能改角色或他人資料。
- [ ] 未登入、登入到期、登出符合 Q-06，每次請求檢查帳號啟用。
- [ ] 角色導向正確，無入住及無分配有提示，重新整理保持正確登入狀態。

### AC-2B 大樓與管理員

- [ ] 系統管理員建立管理大樓；大樓管理員只能讀改自己大樓。
- [ ] 同棟可多人，一人不可兩棟；未授權角色不能分配。
- [ ] 取消分配立即失去原範圍權限，帳號與經手紀錄保留；既有帳號查找符合 Q-08。

### AC-2C 戶別與入住

- [ ] 同棟相同戶號被阻擋，不同棟可重複，樓層戶號支援文字。
- [ ] 同戶並行建立入住最多成功一次，目前及歷史可區分。
- [ ] 更正戶別不改所屬大樓；其他棟管理員不能查看操作。

### AC-2D 邀請碼與加入

- [ ] 原碼只顯示一次，後續不回傳原碼或雜湊；新碼使舊碼失效。
- [ ] 無效、過期、停用、入住結束的碼不能加入，確認加入時重新檢查。
- [ ] 同批次重試不重複，兩分頁加入不同戶最多成功一戶；同戶可加入多位成員。
- [ ] 碼格式期限與重新加入符合 Q-04、09；住戶名單權限正確。

**階段 2 整體驗收：** 從初始化系統管理員出發，不依賴預建大樓與住戶，以畫面完成建立大樓、分配管理員、建立戶別入住、產生邀請碼及住戶加入。共用介面、錯誤提示及資料隔離隨功能驗收。

### AC-3A 包裹管理

- [ ] 管理員登記至有效入住，必填選填正確，重複登記符合 Q-01。
- [ ] 住戶只看自己有效入住；同批次晚加入可看，新批次與搬離者不可看。
- [ ] 搜尋、狀態、分頁及新到舊排序正確，不洩漏碼、密文或雜湊。
- [ ] 更正只限允許狀態及同棟有效入住，已結束入住不能轉移；驗證互動於 3B 整合驗收。

### AC-3B 取件簽收

- [ ] 錯碼、不符大樓、狀態或入住不能驗證；防猜符合 Q-05。
- [ ] 驗證成功仍待領，同包裹只有一筆有效驗證，10 分鐘後不能確認。
- [ ] 未驗證、已取消不能簽收；現場無法簽收符合 Q-03。
- [ ] 同戶兩帳號並行確認最多成功一次；同簽收者有權限時重試得到原結果，失去資格者不能取得。
- [ ] 簽收、包裹、驗證更新一起成功或失敗，驗證與簽收指向同包裹。
- [ ] 完成後不能再取碼或取消；改名不影響簽收者與經手者歷史姓名。
- [ ] 包裹更正、斷線恢復、其他管理員操作符合 BR 及 Q-07，不顯示過期成功畫面。

### AC-3C 異常處理

- [ ] 原因必填，操作者時間由後端記錄，異常取消驗證且不能領取。
- [ ] 再次異常清空前次處理結果，只保留最近一次；已簽收退回不能新增異常。
- [ ] 恢復須填結果並換碼，已結束入住只能退回。

### AC-3D 搬離更替

- [ ] 申請退出仍可操作；個別取消即失去權限，其他成員不變，舊邀請碼失效。
- [ ] 重試撤銷不改時間、不停用後來的新碼。
- [ ] 整戶結束前顯示未領包裹，多表更新一起成功或失敗。
- [ ] 既有異常補充搬離原因；已簽收退回不變，舊包裹不能轉給新人或恢復領取。
- [ ] 新入住看不到舊紀錄，撤銷資格與簽收並行不能繞過權限。

### AC-3E 本機整體驗收

- [ ] 獨立瀏覽器工作階段登入三角色，完成空白大樓至簽收、異常及整戶更替。
- [ ] 兩棟隔離、同戶共用及並行、取消過期失去資格等情境通過。
- [ ] 前端 lint、TypeScript、正式建置通過；後端在獨立測試資料庫驗證交易權限及並行。
- [ ] 實際 API 與 OpenAPI 一致，不以假資料代替驗收。
- [ ] 桌面手機版面、鍵盤操作、載入空資料、網路失敗與登入到期提示可用。
- [ ] Docker 重啟資料保留；測試資料匯出還原成功並留下證據。
- [ ] 啟動與角色操作說明可重現，不含真實密碼；不包含公開部署。
